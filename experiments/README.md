# GA experiments

The current focus is one system, the Narendra plant, and the genome
encodings on it:

```shell
python scripts/run_experiments.py experiments/narendra-genome.json
```

`narendra-genome.json` is the quick setting (population 200, 1500
generations, 8 seeds); `narendra-genome-full.json` the confirming one
(population 300, 3000 generations, 12 seeds). A smaller population than 200
escapes the plateau too rarely to tell the encodings apart.

The same comparison on the Wood–Berry distillation column
(`--benchmark wood-berry`) is `wb-genome.json`:

`wb-genome.json` runs eight encodings -- the four fixed-role variants
(`A-base`, `A-runs`, `A-shuffle`, `A-mixed`), `B-redundant`, `C-two-level`, and
the two free-sequence references -- under one identical GA. It is the quick
setting for iterating on the encoding: population 100, 600 generations, 6
seeds, about 10-15 minutes. `wb-genome-full.json` is the same comparison at
population 300, 3000 generations and 12 seeds, for confirming a result --
several hours.

Each JSON file here describes one experiment on the genome GA: the benchmarks,
how many seeds, the arguments every run shares (`common`), and one entry per
series with the arguments that set it apart (`args`). The encoding is frozen on
`A-base` so that only the GA varies.

| file | step | what varies |
|---|---|---|
| `ga-crossover.json` | 1 | crossover operator, and the genome size cap |
| `ga-diversity.json` | 2 | clone clearing, islands, immigrants, restarts |
| `ga-scheme.json` | 3 | generational, steady-state, (μ+λ), (μ,λ), crowding |
| `ga-selection.json` | 4 | tournament size, truncation, ranking, roulette |

Each also exists as `wb-ga-*.json`, the same series on the Wood–Berry
distillation column (`--benchmark wood-berry`): two inputs, two outputs, four
paths with their own dead times, and an exact reference graph. Its runs use
300 steps with each input held for 10 samples.

Run one, with all cores but two. A status table -- per series: runs finished,
how many below the floor, median, best, and how far the running ones have got,
with an estimate of the time left -- is printed every `--refresh` seconds
(default 60), and a line whenever a run finishes. By default it uses 80 % of the
logical cores (`--cpu 0.6`, or `--jobs N`) at below-normal priority, so the
machine stays responsive; `--priority normal` turns that off. Ctrl+C stops the batch; the
finished runs are kept and the next start resumes.

```shell
python scripts/run_experiments.py experiments/ga-crossover.json
```

Results go to `results/<name>/` (ignored by git), one JSON file per run, and
the report to `results/<name>/report.html`. A job whose result file exists is
skipped, so an interrupted batch resumes; delete the directory to start over.
`--jobs N` sets how many runs go at once, and `--report-only` rebuilds the
report without running anything.

At the full settings (population 300, 3000 generations, 16 seeds) one run
takes about 15–20 minutes, so an experiment of six series is 96 runs: roughly
an hour on 26 workers. For a quick look, copy a file and lower `seeds`,
`--generations`, and `--population` in `common`.

Do not edit `src/` while a batch runs: each run imports the code when it
starts, so later runs would use a different program.

The findings of a finished experiment can be written into the report by adding
a `"findings"` field to its JSON file -- HTML `<li>` items -- and rerunning with
`--report-only`.

## The weekend run: a hundred encodings

`weekend-encodings.json` is generated by `scripts/make_encoding_catalog.py`,
which validates every encoding before writing it: 108 fixed-role encodings in
six groups (number transforms, per-role mixes, analogies from nature,
mutation operators, record shape and addressing, chimeras) and three
references, on the Narendra plant at population 300, 3000 generations, 12
seeds -- 1332 runs, very roughly a day on 22 workers.

```shell
python scripts/run_experiments.py experiments/weekend-encodings.json --stop-after 60
```

The runner keeps the machine awake while it runs (`--allow-sleep` turns that
off), starts no new run after `--stop-after` hours, and interleaves seeds so
an early stop still leaves every encoding with some. With this many series the
status table lists the twelve leaders and one line per group, and the report
draws the six best plus the references while its table lists them all.
Rerunning the same command resumes.
